# XWH AI 官网设计与性能规范

本文件是官网与 demo 封面的现役设计基线。新增页面、改版或新增案例前先读本文件；视觉判断使用 `frontend-design`，性能验收使用 `web-perf` 或浏览器 Performance API。

## 视觉语言

- **底色**：深蓝黑 `#0b1017`，蓝色强调 `#63b8ff`，成功色 `#54c7a4`。
- **字体**：系统无衬线字体栈；不加载外部字体，避免额外请求与字体交换。
- **布局**：单栏主叙事＋双栏卡片网格；移动端 620px 以下切单栏。
- **卡片**：统一深色面板、细边框、克制圆角；不用大面积渐变作为装饰。
- **demo 封面**：浅色底＋白色纸面产品稿＋偏移阴影＋轻微旋转。封面必须展示该 demo 的真实界面/工件，不用流程标签代替成品。

## 封面契约

四个 demo 封面共享同一套语言：

| Demo | 封面内容 |
|---|---|
| Legacy Bridge | 对账窗口、订单/回款数字、匹配与异常条 |
| Price Console | 证据比价面板、价格条、冲突计数 |
| AI Support | 知识库对话、引用编号、离线标记 |
| Northstar | 工程图纸、质量记录、色板 |

新增案例时复制的是**构图原则**，不是代码或内容：浅色舞台、白色工件、硬边偏移阴影、内容相关视觉。

## 双语首屏

- 语言必须在 `<head>` 首屏绘制前确定：读取 `localStorage` 或 `navigator.language`，给 `<html>` 加 `lang-zh` / `lang-en`。
- CSS 只根据 `<html>` 类显示对应语言。
- `site.js` 只负责用户点击后的切换，不在首屏绘制后替换整段文本。
- 反面案例：脚本在 body 末尾才切语言，曾导致手机 CLS `0.61`；修复后为 `0`。

## 性能门槛

生产首页每次改版后，用新浏览器会话测桌面 1440px 与手机 390px：

- LCP < 2.5s；
- CLS < 0.1；
- 长任务 0；
- 无横向溢出；
- 首页外部请求保持 0；
- 图片必须压缩并写宽高；视频不进入首屏关键路径。

2026-11-25 基线：桌面 LCP 1.87s、手机 LCP 0.67s、CLS ≈0、长任务 0、外部请求 0。

## 验收流程

1. `npm run build:pages`
2. `npm run scan`
3. `npm run scan:public`
4. 桌面/手机浏览器检查控制台、失败请求、横向溢出
5. 生产部署后复测 Performance API
6. 截图人工审查封面是否统一、信息是否清楚

## 技能与边界

- 设计：`frontend-design`
- 性能：项目级 `web-perf`；工具不可用时用 Playwright Performance API，并说明未测项
- 部署：项目级 `wrangler` / `netlify-deploy` / `xwh-deploy-pages`
- 不安装来源不明、有未解决 Critical 审计或职责重叠的技能
